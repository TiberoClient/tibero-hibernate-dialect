# Tibero Hibernate Dialect

Tibero DB 를 **Spring / Hibernate**(JPA) 와 함께 사용하기 위한 Hibernate Dialect 구현입니다.
Spring Boot JPA, Spring Data JPA 등에서 Tibero 를 데이터베이스로 사용할 때 이 dialect 를 설정하면 됩니다.

## 최신 버전

| Hibernate | dialect | JAR |
|---|---|---|
| **6.6.x** | **6.6.1** | `tibero-hibernate-dialect-6.6.1.jar` |

변경 내역은 [docs/CHANGELOG.md](docs/CHANGELOG.md) 를 참고하세요.
6.6.0 에서 올리신다면 **[업그레이드 시 확인할 것](#업그레이드-시-확인할-것)** 을 먼저 읽어 주세요.

## 빠른 설정 (Spring Boot)

```properties
spring.jpa.database-platform=com.tmax.tibero.hibernate.dialect.TiberoDialect
spring.datasource.driver-class-name=com.tmax.tibero.jdbc.TbDriver
spring.datasource.url=jdbc:tibero:thin:@<호스트>:<포트>:<SID>
spring.datasource.username=<계정>
spring.datasource.password=<비밀번호>
```

6.6.1 부터는 **`database-platform` 을 생략해도** dialect 가 자동으로 인식됩니다.
짧은 이름 `Tibero` 로 지정할 수도 있습니다.

JAR 선택과 dependency 추가 방법은 [docs/setup.md](docs/setup.md) 를 참고하세요.

## 요구 사항

| |                                        |
|---|----------------------------------------|
| Hibernate ORM | 6.6.x (6.6.56.Final 로 검증)              |
| Java | 11 이상                                  |
| Tibero | **7.2.6 이상** (7.2.6 FS02_PS06 으로 검증) — 아래 각주 참고 |
| JDBC 드라이버 | `tibero7-jdbc-11.jar` 등 Tibero 제공 드라이버 |

> Tibero 6 이하에 붙이면 기동 시 `HHH000511` 경고가 뜹니다. 다만 이 검사는 **메이저 버전까지만**
> 봅니다 — JDBC 드라이버가 마이너 버전을 `0` 으로 보고해 정상적인 7.2.6 서버도 `7.0` 으로
> 읽히기 때문입니다. **7.2.6 하한은 자동으로 검사되지 않으므로** 서버 버전은 따로 확인하세요.

## 업그레이드 시 확인할 것

6.6.0 → 6.6.1 에서 **동작이 달라지는 것이 네 가지** 있습니다. 자세한 내용과 대응은
[docs/user-notes.md](docs/user-notes.md) 에 있습니다.

**① IDENTITY 컬럼 DDL 이 바뀝니다**
`generated as identity` → `generated by default as identity`.
새로 만드는 스키마에만 적용되고 **기존 테이블은 전환하지 않아도 됩니다** —
`persist`·`merge`·`update`·`delete`·채번 ID 회수가 두 스키마에서 동일하게 동작합니다.

**② month / quarter / year 연산이 시각을 보존합니다**
`ts + 1 month` 가 이전에는 `2024-02-29 00:00:00`, 이제는 `2024-02-29 10:20:30` 을 돌려줍니다.
결과가 `00:00:00` 인 것에 의존하는 쿼리가 있으면 `trunc()` 를 명시하세요.

**③ float / double DDL 이 `binary_float` / `binary_double` 로 나갑니다**
기존 NUMBER 기반 `float(p)` 컬럼과 스키마를 맞추려면 `ddl-auto` / `validate` 설정을 확인하세요.

**④ 네이티브 쿼리의 `NUMBER(p,0)` 결과 타입이 `Integer` / `Long` 으로 통일됩니다**
`NUMBER(1,0)` 이 `Boolean`, `NUMBER(3,0)` 이 `Byte`, `NUMBER(5,0)` 이 `Short` 였던 것이
모두 `Integer` 가 됩니다. DB 쪽 범위가 자바 타입보다 넓어 `NUMBER(3,0)` 의 `200` 이
`JDBC-590749` 로 깨지고 `NUMBER(1,0)` 의 `7` 이 조용히 `true` 가 되던 것을 고친 결과입니다.
**엔티티 매핑은 영향이 없고**, 네이티브 쿼리에서 이전 타입으로 캐스팅하는 코드만 조정하면 됩니다.

## JSON 을 쓰신다면

JSON 매핑에는 **JSON 직렬화 라이브러리가 별도로 필요**합니다.

```gradle
runtimeOnly 'com.fasterxml.jackson.core:jackson-databind'   // 또는 Yasson 등 JSON-B 구현체
```

없으면 런타임에 `Could not find a FormatMapper for the JSON format` 이 납니다.
dialect 가 아니라 Hibernate 의 자동 탐지 방식이며 Oracle 에서도 동일합니다.
이 dialect 는 Jackson 에 의존하지 않으므로 사용하는 쪽에서 추가하세요.

네이티브 `json` 컬럼만 필요하고 직렬화는 앱이 직접 하겠다면
`@Column(columnDefinition = "json")` + `String` 으로 라이브러리 없이 쓸 수 있습니다.
