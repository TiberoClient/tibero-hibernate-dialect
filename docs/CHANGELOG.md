# Changelog

이 프로젝트의 릴리즈별 변경 사항입니다.  
형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/) 를 따릅니다.

## [6.6.1]

Hibernate ORM **6.6.x** 대상 dialect 개선 및 결함 수정입니다.  
JAR: `tibero-hibernate-dialect-6.6.1.jar`

### Fixed

- **NVARCHAR2 길이 상한**을 Tibero 실측값 `32766`으로 맞춤.  
  이전에는 VARCHAR2 상한(`65532`) 을 그대로 써서 `@Nationalized` 긴 컬럼 DDL 이 실패할 수 있었음
- **`float` / `double` DDL**이 `float(p)`(내부적으로 NUMBER) 로 나가던 문제를 수정.  
  이제 precision 에 따라 `binary_float` / `binary_double`로 매핑되어 IEEE 정밀도를 유지함
- HQL `cast(... as Float/Double)`이 `float(53)` 등으로 생성되어 Tibero 에서 실패하던 문제 수정
- `mod` / `power` / `atan2`를 잘못 재등록해 반환 타입이 좁아지던 문제 수정 (base 함수 등록 유지)
- `resolveSqlTypeDescriptor`의 `BLOB` 분기 fall-through 정리
- **JSON 컬럼이 있는 엔티티의 스키마 생성 실패**를 수정.  
  Oracle 전용 `check (col is json)` 술어가 딸려와 `create table` 이 `JDBC-8014` 로 깨졌음.  
  `TiberoJsonBlobJdbcType` 을 추가해 그 check 를 내지 않도록 함
- **페이징과 비관적 락을 함께 쓸 때 나던 SQL 문법 오류**를 수정.  
  `… fetch first ? rows only for update` 가 `JDBC-8004` 로 실패했음.  
  `TiberoSqlAstTranslator.determineLockingStrategy()` 에서 판정하도록 함
- **저장 프로시저의 이름 파라미터가 위치로 바인딩되던 문제**를 수정.  
  선언 순서와 다르게 등록하면 **예외 없이 값이 뒤바뀌었음**. `name => ?` 로 렌더함.  
  옵트인 설정 `hibernate.query.pass_procedure_paramater_names` 가 켜졌을 때만 적용됨
- **`str()` 의 결과가 세션 NLS 설정에 좌우되던 문제**를 수정.  
  `str(날짜)` 가 접속 환경마다 다른 문자열을 돌려주었음. 형식 없는 `to_char` 로 직접
  등록하던 것을 걷어내 날짜·시각을 ISO-8601 로 고정함.  
  **숫자는 여전히 `NLS_NUMERIC_CHARACTERS` 를 탐** — Oracle 도 동일함
- **시퀀스 생성 DDL 의 공백 불일치**를 수정.
  일반 경로만 `increment by  50` 처럼 공백이 두 칸이라 스키마 비교 도구에서
  없는 차이가 잡혔음
- **Java 11 타깃 빌드가 깨져 있던 문제**를 수정.  
  `VERSION_11` 설정인데 소스에 Java 14+ 문법이 남아 있었음. Hibernate 6.6 baseline 에
  맞춰 정리했고 산출물은 major 55 로 빌드됨

- **`extract(epoch from <DATE 필드>)` 가 실패하던 문제**를 수정.  
  `at time zone` 은 타임존 정보를 가진 값에만 쓸 수 있어 `JDBC-11003` 이 났음.  
  인자가 DATE 일 때만 `from_tz` 식으로 갈아끼움. `TIMESTAMP` 경로는 그대로임
- **HQL 파생 테이블(FROM 절 서브쿼리) 이 실패하던 문제**를 수정.  
  `from (select ...) d` 가 `… ) d1_0(x)` 로 렌더되어 `JDBC-8022 Invalid end of SQL` 이 났음.  
  컬럼 별칭을 서브쿼리 select 절 안쪽으로 옮겨 `(select n x from T) d1_0` 형태로 냄
- **`NUMBER(p,0)` 컬럼을 읽을 때 값이 깨지던 문제**를 수정. 아래 Upgrade notes 참고
- **페이징 + 비관적 락에서 정렬 순서가 보장되지 않던 문제**를 수정.  
  바깥 쿼리에 `order by` 가 없어 **예외 없이 다른 순서**로 반환됐음 — 실행계획이
  해시 조인으로 바뀌면 드러남. 바깥 래퍼에도 정렬 사양을 복사함
- **`LimitHandler` 의 공유 가변 상태**를 제거.  
  싱글턴이 `processSql` 에서 덮어쓴 플래그를 호출자가 나중에 읽어, 동시 실행 시
  **예외 없이 다른 페이지**가 나올 수 있었음. 호출마다 새 인스턴스를 돌려줌
- **최소 지원 버전이 검사되지 않던 문제**를 수정.  
  `getMinimumSupportedVersion()` 을 재정의하지 않아 하한이 `0.0.0` 이었고 Tibero 4 서버에  
  붙여도 경고가 없었음. 하한을 `7.0` 으로 두어 Tibero 6 이하에서 `HHH000511` 이 뜸

### Added

- **`TiberoSqlAstTranslator`**  
  - recursive CTE (`WITH`, `RECURSIVE` 키워드 없음)  
  - INSERT conflict / optional secondary table update → `MERGE`  
  - JOIN 이 있는 UPDATE 의 inline view 에뮬레이션  
  - 빈 `OVER ()` 윈도우 보정
- **`binary_float` / `binary_double` 전용 JDBC 바인딩**  
  표준 `setFloat` / `setDouble`이 NUMBER 로 바인딩되는 Tibero JDBC 특성을 우회해,  
  IEEE 극값·큰 지수·NaN / Infinity 왕복을 지원
- **`@Struct` (object UDT) 매핑**
  값 객체(`@Embeddable`) 를 UDT 컬럼 하나에 담음. 성분 단위 조회·부분 갱신 지원
- **네이티브 배열 컬럼 (VARRAY)**
  `String[]`·`Integer[]` 등을 배열 UDT 컬럼으로 매핑. `@Struct` 배열도 지원
- **JSON 집계 임베더블** (`@JdbcTypeCode(SqlTypes.JSON)` + `@Embeddable`)
  값 객체를 JSON 컬럼 하나에 담고 **안쪽 필드를 SQL 로 다룰 수 있음** —
  `where p.addr.city = ?`, `select p.addr.zip`, `update … set p.addr.city = ?`.
  3단 중첩과 배열 필드까지 동작함
- **dialect 자동 인식**
  `hibernate.dialect` 를 지정하지 않아도 접속한 DB 를 보고 Tibero dialect 를 고름.
  짧은 이름 `Tibero` 로도 지정 가능
- **Tibero 고유 예약어 자동 인용**
  `least`·`flashback`·`connect_by_root` 등 실측으로 확정한 71종을 등록함.
  `hibernate.auto_quote_keyword=true` 일 때 적용되는 옵트인 기능임
- **대량 배치 로딩 분할**
  `byMultipleIds` 같은 다중 키 조회를 500건씩 나눠 보냄. Tibero 는 IN 원소 수에
  한도가 없지만 **파스 비용이 원소 수의 제곱으로** 늘어남 — 3,000키 조회가
  1,411ms 에서 171ms 로 줄었음
- Dialect 훅·기능 플래그·시간/캐스트 패턴·DML 관련 테스트 보강

### Changed

- 부동소수·국가별 문자열·SQL AST / DML 경로를 Tibero 7.2.6 실측 기준으로 정합
- **페이징 + 비관적 락의 쿼리 횟수가 `1+N` 에서 1회로 줄었음.**  
  위 문법 오류 수정은 follow-on locking 으로 우회한 것이라, 잠금 없는 조회 1회 뒤에  
  행마다 잠금 문장이 하나씩 나가고 락 획득 시점도 늦었음. Oracle 의 locking wrapper 를  
  이식해 페이징을 서브쿼리로 밀고 `for update`를 바깥에 두는 형태로 바꿈.  
  조인 없는 단순 페이징 경로에 적용되며, 조인·다중 루트·DISTINCT·GROUP BY·집합 연산·  
  `WITH TIES`는 기존대로 follow-on 으로 처리됨 (문법 오류는 모든 경로에서 발생하지 않음)
- **month / quarter / year 연산이 TIMESTAMP 의 시각을 보존**하도록 변경.  
  이전에는 `trunc(ts,'MONTH')` 기반 수식이라 `+ 1 month` 등이 시·분·초를 `00:00:00`으로  
  버렸음. `add_months` 기반으로 바꿔 시각을 유지하며, 월말 클램프(`1/31 + 1개월 = 2/29`) 는  
  그대로임. **Hibernate `OracleDialect`는 지금도 시각을 버리므로 Oracle 과 결과가 다름**
- **IDENTITY 컬럼 DDL**이 `generated as identity`(= `always`) 에서  
  `generated by default as identity`로 바뀜. `@GeneratedValue(strategy = IDENTITY)`로  
  만들어지는 컬럼에 **ID 를 직접 지정한 INSERT 가 허용**됨. 표준 `generated … as identity`  
  문법을 쓰는 Hibernate dialect 6종(Oracle · PostgreSQL · DB2 · H2 · HANA · HSQL) 이 모두  
  `by default`인 것에 맞춘 것임. `persist()`로 저장하는 통상 경로는 변화 없음

### Upgrade notes (6.6.0 → 6.6.1)

동작이 달라지는 것이 넷, 미리 준비할 것이 둘입니다. **대응 방법과 실측 SQL 은
[user-notes.md](user-notes.md) 에 있습니다.**

| | 무엇이 달라지나 | 대응 |
|---|---|---|
| IDENTITY DDL | `generated as identity` → `generated by default as identity` | 새 스키마에만 적용. **기존 테이블은 전환하지 않아도 됩니다** |
| month/quarter/year 연산 | `ts + 1 month` 가 시각을 보존 (`00:00:00` → `10:20:30`) | `00:00:00` 을 전제한 쿼리는 `trunc()` 를 명시 |
| float / double DDL | `float(p)` → `binary_float` / `binary_double` | `ddl-auto=validate` 를 쓰면 스키마 확인 |
| 네이티브 쿼리의 `NUMBER(p,0)` | `Boolean`/`Byte`/`Short` → `Integer`(`p≤10`) · `Long`(`p≤19`) | 이전 타입으로 캐스팅하는 코드만 조정. **엔티티 매핑은 영향 없음** |
| `str()` 결과 형식 | 날짜·시각이 세션 NLS 와 무관하게 ISO-8601 로 고정 | 이전 형식에 의존하면 `to_char(x,'형식')` 으로 명시 |
| NVARCHAR2 상한 | `65532` → `32766` | 그 이상을 가정한 매핑이 있으면 조정 |

**미리 준비할 것**

- **JSON 매핑에는 Jackson 또는 JSON-B 구현체가 필요합니다.** 없으면 런타임에
  `Could not find a FormatMapper for the JSON format` 이 납니다. dialect 가 아니라
  Hibernate 의 자동 탐지 방식이며 Oracle 도 동일합니다
- **저장 프로시저의 이름 파라미터는 옵트인입니다.** 기본값에서는 Oracle 을 포함한 모든
  dialect 가 위치 바인딩을 씁니다

**그 밖**

- **Tibero 6 이하에 붙이면 `HHH000511` 경고가 뜹니다.** 동작을 막지는 않습니다.
  ⚠️ 이 검사는 메이저 버전까지만 봅니다 — 드라이버가 마이너를 `0` 으로 보고해 정상적인
  7.2.6 서버도 `7.0` 으로 읽힙니다. **7.2.6 하한은 검사되지 않으므로** 따로 확인하세요
- **예약어 자동 인용은 옵트인입니다.** 켜면 인용된 컬럼명의 대소문자가 고정되므로
  예약어를 컬럼명으로 쓸 때는 대문자로 선언하는 편이 안전합니다
- **dialect 자동 인식이 켜집니다.** `hibernate.dialect` 를 명시하고 있으면 그 값이 우선하므로
  영향이 없습니다
- **follow-on 경로로 잠그는 쿼리에는 `@Version` 을 두는 편이 안전합니다.** 조인·다중 루트·
  DISTINCT·집합 연산은 여전히 잠금 없는 조회를 먼저 합니다

## [6.6.0]

Hibernate ORM **6.6.x**용 Tibero dialect 초기 공개입니다.  
JAR: `tibero-hibernate-dialect-6.6.0.jar`

### Added

- Hibernate 6.6 API 에 맞춘 `TiberoDialect`
- 시퀀스 / IDENTITY, LimitHandler(페이징), 락·예외 변환 등 기본 지원
- `TiberoSequenceSupport`, `TiberoIdentityColumnSupport`, `TiberoLimitHandler` 등 구성
